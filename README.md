# Smart Credit — scoring

Отдельный сервис оценки риска для **учебного прототипа** кредитного кабинета. Сервис принимает синтетические финансовые показатели и возвращает балл 0–100, рассчитанные факторы и предварительную рекомендацию. Чем выше балл, тем лучше оценка. Итоговое решение по заявке принимает backend.

## Запуск

Для HTTP-сервиса нужен Python 3.12+; сторонние библиотеки при запуске не требуются.

```sh
python -m scoring.app
python -m unittest discover -s tests -v
```

По умолчанию HTTP-сервис слушает `127.0.0.1:8001` и использует `SCORING_MODEL=logreg_v1` — обученную на синтетических данных логистическую регрессию. Для контейнера задайте `HOST=0.0.0.0`, при необходимости `PORT=8001`. `SCORING_MODEL=rules_v1` выбирает прежние детерминированные правила. Проверка доступности: `GET /health`.

Контейнер собирается командой `docker build -t smart-credit-scoring .` и запускается командой `docker run --rm -p 8001:8001 smart-credit-scoring`. Сервис не хранит состояние и не обращается к внешним системам; несколько экземпляров можно запускать за балансировщиком. Образ использует Python 3.12.10 и не устанавливает пакеты из сети во время сборки.

## Контракт

`POST /v1/score` с `Content-Type: application/json`. Источники истины: [схема запроса](contracts/scoring.schema.json), [схема ответа](contracts/scoring-response.schema.json) и [OpenAPI](contracts/openapi.json). Все денежные значения — целые рубли.

```json
{
  "application_id": "SC-EXAMPLE-1",
  "monthly_revenue": 2400000,
  "monthly_expenses": 1500000,
  "existing_debt": 500000,
  "monthly_debt_payments": 90000,
  "overdue_count": 0,
  "requested_amount": 1500000,
  "term_months": 12
}
```

Ответ для этого примера при модели по умолчанию (`logreg_v1`):

```json
{
  "decision": "approved",
  "score": 97,
  "approved_amount": 1500000,
  "reasons": [
    "Операционный поток покрывает оценочный платёж по запрошенной сумме.",
    "В синтетической кредитной истории нет просрочек."
  ],
  "factors": {
    "operating_cash_flow": 900000,
    "operating_margin": 0.375,
    "estimated_new_monthly_payment": 138951.76,
    "debt_service_share": 0.2544,
    "existing_debt_to_annual_revenue": 0.0174,
    "overdue_count": 0
  }
}
```

`decision` и `approved_amount` — рекомендации скоринга, не утверждённый кредит. Поле `estimated_new_monthly_payment` всегда относится к **запрошенной** сумме, в том числе при `counter_offer`. Ошибки имеют формат `{"error": "...", "message": "..."}`; неверное поле даёт HTTP 422, некорректный JSON — 400, неверный Content-Type — 415.

[Подробное описание входа и границ ответственности](docs/INTEGRATION.md).

## Синтетические данные и логистическая регрессия

Генератор `training/generate_synthetic.py` создаёт `data/synthetic_v1/train.csv` (20 000 заявок), `test.csv` (5 000 заявок) и `generation.json`. Фиксированный seed позволяет воспроизвести файлы. Метка `default_12m` равна 1, если при симуляции следующих 12 месяцев денег не хватило на платежи как минимум в двух месяцах. Это выдуманный исход, не история реальных клиентов. [Подробная логика и оценка модели](docs/SYNTHETIC_ML.md).

```sh
python -m pip install -r requirements-ml.txt
python -m training.generate_synthetic
python -m training.train_logreg
```

Обучение сохраняет коэффициенты и параметры нормализации в `scoring/artifacts/logreg_v1.json`. Для инференса `scikit-learn` не требуется: сервис читает этот JSON и считает логистическую функцию средствами стандартной библиотеки. На отложенной синтетической выборке ROC AUC = **0,910**, Brier = **0,114** (у константного прогноза 0,225). Прежняя модель `rules_v1` для входа из примера возвращает `score: 100`; остальные поля совпадают с показанным ответом.

## Расчёт и замена модели

`scoring/app.py` обрабатывает HTTP, `scoring/service.py` валидирует вход и собирает ответ, `scoring/metrics.py` считает общие финансовые показатели. `scoring/models.py` задаёт интерфейс `predict_score(features) -> int`. `rules_v1` использует фиксированные штрафы; `logreg_v1` прогнозирует вероятность синтетического исхода и переводит её в `round(100 × (1 − p))`. `scoring/recommendation.py` формирует рекомендацию и причины по финансовым показателям независимо от выбранной модели балла. Для нового кредита платёж оценивается по условной стресс-ставке 20% годовых. Эта ставка не является условием кредитного предложения.

Новая модель должна реализовать тот же интерфейс и возвращать целое число 0–100. Добавьте её в реестр `get_model()`; экземпляр загружается один раз на процесс. При замене модели рекомендация остаётся отдельной детерминированной политикой; её пороги нужно проверить на согласованность с новой шкалой. HTTP и JSON-контракт сохраняются. Смена смысла балла, шкалы или входных признаков потребует новой версии API и согласования с backend. Синтетическая ML-модель не калибрована на реальных клиентах и не подходит для реальных кредитных решений.
