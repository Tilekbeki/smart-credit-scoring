# Smart Credit — scoring

Отдельный сервис оценки риска для **учебного прототипа** кредитного кабинета. Сервис принимает синтетические финансовые показатели и возвращает только целый балл 0–100: чем выше балл, тем лучше оценка. Это не вероятность дефолта, не банковский скоринг и не решение о выдаче кредита.

## Запуск

Нужен Python 3.12+; сторонние библиотеки не требуются.

```sh
python -m scoring.app
python -m unittest discover -s tests -v
```

По умолчанию HTTP-сервис слушает `127.0.0.1:8001`. Для контейнера задайте `HOST=0.0.0.0`, при необходимости `PORT=8001`. `SCORING_MODEL=rules_v1` выбирает текущую детерминированную модель. Проверка доступности: `GET /health`.

Контейнер собирается командой `docker build -t smart-credit-scoring .` и запускается командой `docker run --rm -p 8001:8001 smart-credit-scoring`. Сервис не хранит состояние и не обращается к внешним системам; несколько экземпляров можно запускать за балансировщиком. Образ использует Python 3.12.10 и не устанавливает пакеты из сети во время сборки.

## Контракт

`POST /v1/score` с `Content-Type: application/json`. Источники истины: [схема запроса](contracts/scoring.schema.json), [схема ответа](contracts/scoring-response.schema.json) и [OpenAPI](contracts/openapi.json). Все денежные значения — целые рубли.

```json
{
  "application_id": "SC-EXAMPLE-1",
  "monthly_revenue": 2400000,
  "monthly_expenses": 1500000,
  "existing_debt": 500000,
  "monthly_debt_payments": 90000,
  "overdue_count": 0,
  "requested_amount": 1500000,
  "term_months": 12
}
```

Ответ для этого примера: `{"score": 100}`. Никаких `decision`, `approved_amount`, условий кредита или причин в успешном ответе нет. Ошибки имеют формат `{"error": "...", "message": "..."}`; неверное поле даёт HTTP 422, некорректный JSON — 400, неверный Content-Type — 415.

[Подробное описание входа, границ ответственности и перехода со старого контракта](docs/INTEGRATION.md).

## Расчёт и замена модели

`scoring/app.py` обрабатывает HTTP, `scoring/service.py` валидирует и нормализует вход, а `scoring/models.py` задаёт интерфейс `predict_score(features) -> int` и выбирает реализацию. Текущий `scoring/rules.py` использует фиксированные штрафы за низкую маржу, высокую долговую нагрузку, текущий долг и просрочки. Для нового кредита платёж оценивается по условной стресс-ставке 20% годовых. Эта ставка не является условием кредитного предложения.

Обученная модель должна реализовать тот же интерфейс и возвращать целое число 0–100. Добавьте её в реестр `get_model()`; экземпляр загружается один раз на процесс. HTTP, JSON-контракт и backend при такой замене не меняются. Смена смысла балла, шкалы или входных признаков потребует новой версии API и согласования с backend. Для реальной модели нужны размеченные данные, независимая проверка качества и калибровка; текущий балл на этом не основан.
