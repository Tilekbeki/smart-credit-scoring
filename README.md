# Smart Credit — scoring

Отдельный сервис объяснимой оценки для учебного прототипа «Умный кредитный кабинет». Входные данные синтетические; формула и пороги придуманы для показа самостоятельного клиентского пути. Это **не банковский скоринг** и результат не является кредитным решением.

## Запуск

```sh
python3 -m scoring.app
```

По умолчанию сервис слушает `127.0.0.1:8001`. Для Docker: `HOST=0.0.0.0 PORT=8001 python3 -m scoring.app`. Проверка: `GET /health`.

## Контракт

`POST /v1/score`, `Content-Type: application/json`. Схемы: [запрос](contracts/scoring.schema.json) и [ответ](contracts/scoring-response.schema.json).

```json
{
  "application_id": "example-1",
  "monthly_revenue": 2400000,
  "monthly_expenses": 1500000,
  "existing_debt": 500000,
  "monthly_debt_payments": 90000,
  "overdue_count": 0,
  "requested_amount": 1500000,
  "term_months": 12
}
```

`monthly_expenses` не включает платежи по долгам. Суммы выражены в рублях. Ответ содержит `decision` (`approved`, `counter_offer` или `rejected`), `score` 0–100, `approved_amount` в рублях, человекочитаемые `reasons` и численные `factors`. При ошибке входа сервис возвращает 400/415/422 с полями `error` и `message`.

## Учебные правила

1. Месячный операционный поток = выручка − расходы. Для оценки доступности платежа используется аннуитет при условной стресс-ставке 20% годовых. Это **не ставка предлагаемого кредита**.
2. Запрос одобряется целиком при отсутствии просрочек, положительной операционной марже от 15%, умеренной текущей задолженности и совокупных платежах не выше 45% операционного потока.
3. При умеренной нагрузке сервис автоматически предлагает меньшую сумму: совокупные платежи по ней должны помещаться в 55% потока. Просрочки или невысокая маржа дополнительно уменьшают лимит.
4. При трёх просрочках, неположительном потоке, марже ниже 10%, чрезмерном текущем долге или невозможности предложить практически полезную меньшую сумму ответ — `rejected`. Ручного рассмотрения в сценарии прототипа нет.

Все пороги зафиксированы в `scoring/app.py`. Балл служит объяснимым индикатором для интерфейса; итоговая ветка определяется правилами. Ни балл, ни модель не обучены на реальных данных.
